# AskHR 全景工作区实施计划

**目标：** 以个人、团队、组织三个数据范围替代员工自助入口，并保留统一 AI 对话能力。

**架构：** 复用现有个人页面、固定 header、shadcn 组件与 Copilot。团队与组织工作区使用共享看板及独立业务数据，业务入口通过统一上下文契约打开同一对话组件；薪酬诊断继续使用原流程。

**技术栈：** React 19、TypeScript、shadcn/Base UI、Tailwind 4。

1. 扩展 `features/hr/data.ts` 路由、`icons.ts` 图标、`sidebar.tsx` 导航；原员工页面保留为个人全景。
2. 新建 `panorama-data.ts`/JSON，按参考 HTML 的可见页面迁移团队六个、组织八个 Tab 数据；清理隐藏菜单、人物切换和冲突指标。
3. 新建 `panorama.tsx`，实现固定 header Tab、范围/周期、指标、图表、数据表与指标口径。窄工作区按容器宽度收敛为单列。
4. 扩展 store 的业务 AI 上下文入口；新增 `business-intent.ts`，统一专家、技能、来源与快照；保留原个人 AI 按钮。新增看板场景基于相同快照输出对应分析与建议，避免匹配到无关场景。
5. 将新路由接入现有 Copilot/历史会话/全屏转换。组织薪酬入口复用 DiagnosisFlow，不复制流程。
6. 验证三个全景导航及所有 Tab、个人既有按钮、团队分析上下文与对话、组织薪酬入口、历史全屏及 1280 响应式。运行 lint、token 和构建检查。

验收：原个人六页和现有 AI 流程无损；团队六页和组织八页可浏览；页面按钮仅预填右侧对话，发送后共用历史；上下文为触发时快照，不随页面切换修改；菜单与对话入口保持现有语义。
