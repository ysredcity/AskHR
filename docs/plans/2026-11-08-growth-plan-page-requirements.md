## 1. 目标与改动范围

产物形式为 HTML 网页，制品卡片展示员工成长计划的 `.html` 文件名与“HTML 网页 · 成长计划”描述，不展示预设文件大小。

本需求仅调整生成完成后的「成长计划」产物页面，使用户能看清自身优势与待提升项、适合的发展方向，以及对应的学习和带教安排。

**范围起点：既有流程生成计划并打开产物页面；范围终点：用户在页面中阅读、查看详情和局部编辑计划。**

| 范围 | 说明 |
| --- | --- |
| 本次调整 | 最终成长计划页面的信息结构、内容字段、章节布局、详情查看、局部编辑及相关展示状态 |
| 保持现状 | 首页与业务入口、对话消息、思考与执行过程、员工综合评价、澄清表单、目标岗位选择、推荐追问、生成步骤和确认机制 |
| 继续复用 | 现有产物容器、打开与关闭方式、全屏能力、同一产物修订与撤销能力 |
| 不新增 | 独立管理页、审批、报名、导师预约、外部通知、跨刷新存储 |

本文是本次页面调整的独立评审与开发依据。此前场景文档中的前置流程不属于本次修改范围，不以重做成长计划页面为由一并调整。

## 2. 页面承接的数据

本页面使用既有会话已确认的数据，不重新询问用户，也不默认重选目标。

| 数据 | 使用规则 |
| --- | --- |
| 员工身份 | 与“我的成长”共用姓名、部门、当前岗位、职级等信息 |
| 个人评价依据 | 使用现有绩效反馈、经历及发展记录；不把其他人物的资料作为当前员工事实 |
| 目标岗位及方向 | 严格采用用户实际选中并确认的岗位和所属方向 |
| 计划条件 | 使用已确认的起止日期、周期及每周学习投入 |
| 计划内容 | 承接分析、发展建议、课程、案例、实践与带教内容，按本文结构呈现 |
| 修订状态 | 读取当前计划修订号及已有撤销状态，不维护第二份独立计划 |

页面内容所需的数据字段可在后续实现时补充，但不改变前置对话流程、表单字段或用户操作步骤。当前预设员工为张益达、高级产品经理 P6；示例目标为资深产品经理 P7，实际展示以本次已选目标为准。

## 3. 页面结构与内容要求

### 3.1 总体布局

采用单份纵向文档，按「现状判断 → 发展选择 → 学习行动 → 带教支持」组织。四个核心章节均直接可读，不藏在默认折叠区，也不拆成用户必须切换才能看到的内容 Tabs。

页面顺序：

1. 计划概览。
2. 优劣势分析。
3. 建议发展方向。
4. 学习计划：课程学习、标杆案例、应用实践与阶段成果。
5. 辅导带教安排。
6. 待确认事项。

正文顶部设置轻量章节目录：优劣势分析 / 建议发展方向 / 学习计划 / 辅导带教。点击定位同一文档内章节，不切换数据或打开新面板。窄面板目录换行；正文以单列为主，宽屏可将优势和待提升项并排。沿用现有产物全屏与关闭能力，不增加第二套工具栏。

### 3.2 计划概览

| 内容 | 展示要求 |
| --- | --- |
| 标题 | 张益达的成长计划；展示修订号 |
| 个人摘要 | 姓名、部门、当前岗位与职级，来自同一档案；不重复完整个人履历 |
| 发展目标 | 突出用户实际选中的目标岗位与所属方向，不以系统推荐覆盖用户选择 |
| 时间条件 | 起止日期、总天数、每周学习投入 |
| 一句话概述 | 本周期重点提升什么，计划通过什么成果验证；随目标岗位变化 |

示例：面向资深产品经理 P7，以数据验证、产品战略和规模化推广为本周期的发展重点，通过验证方案、产品路线图及推广复盘积累成果。

90 天是本次计划周期，不承诺 90 天内完成晋级。概览不重复铺开个人综合信息评价全文。

### 3.3 优劣势分析

回答「哪些能力可以发挥，哪些方面需要优先提升」。章节标题保留「优劣势分析」，内部使用「优势」「待提升项」，不将资料缺失描述为缺陷。

每条分析包含：能力项、结论、依据、对目标岗位的意义。每类建议 2–3 项，优先展示有事实依据的内容。

| 类型 | 当前员工的内容示例 | 依据与表达边界 |
| --- | --- | --- |
| 优势 | 从真实业务问题出发推动产品落地 | 引用主管反馈，说明可作为更复杂产品规划的基础 |
| 优势 | 主动推进跨团队协作 | 引用主管反馈，说明可支持多方需求对齐与推广 |
| 待提升 | 数据验证与效果评估 | 主管反馈明确建议提升；需建立假设、指标和验证闭环 |
| 待提升 | 规模化推广能力 | 主管反馈明确建议提升；需沉淀可复用的推广方法 |
| 待核实 | 目标岗位的产品战略要求及当前差距 | 发展记录可说明学习方向，不能仅据课程进度判定能力不足；岗位标准待确认 |

每项提供简短依据说明。可展开查看相关绩效期、反馈或发展记录，但核心结论默认可见。没有真实量化评估时不画能力雷达图、不生成分数或声称已达到某技能等级。

### 3.4 建议发展方向

回答「为什么选择这个方向，本周期具体往哪里发展」。本章节解读已确认目标，不重复澄清表单里的岗位目录。

- 已选目标：岗位、方向；若用户选了非首要推荐岗位，以用户选择为准。
- 适配理由：已有优势如何支持该方向，以及需要补足的关键能力。
- 发展重点：建议 2–3 项，每项包含关联分析、目标状态、验证成果和优先级。
- 阶段路径：周期内先建立方法、再应用验证、最后复盘沉淀；30/60/90 天仅作为默认时间划分，按实际周期调整。
- 备选方向：最多一条简要提示，只在有明确依据时展示；不放第二套岗位单选组件。

发展重点示例：

| 重点 | 关联分析 | 本周期目标 | 验证成果 |
| --- | --- | --- | --- |
| 数据验证 | 主管建议提升数据验证能力 | 能对一个产品需求提出假设、指标和验证方法 | 一份需求验证方案及结果复盘 |
| 产品战略 | 与目标岗位相关，具体岗位要求待确认 | 将业务问题转化为可讨论的路线图与取舍依据 | 一份产品路线图及决策说明 |
| 规模化推广 | 主管建议提升规模化推广能力 | 从一次实际推广中提炼可复用的方法 | 一份推广方案或复盘清单 |

本页面读取已经确认的目标岗位，不提供第二套岗位选择器。既有流程传入新的计划版本时，页面展示对应版本的目标与内容。

### 3.5 学习计划

回答「学什么、参考什么、怎么应用、何时交付」。课程和标杆案例是两类明确可识别的内容，不再只用一句“学习资源”统称。

#### A. 课程学习

每条课程包含：课程名称、对应发展重点、推荐理由、核心内容、预计时长、计划时间、学后产出、来源。默认建议 2–3 门，按时间预算控制数量。

已配置且有可预览内容的课程提供「查看课程」；只有主题建议时显示「待匹配课程」，展示建议主题与预计投入，不伪装成已存在的课程，不提供空详情或报名成功反馈。

#### B. 标杆案例

每条案例包含：案例名称、对应发展重点、推荐理由、重点观察的问题、计划研读时间、预计时长、借鉴产出、来源。默认建议 1–2 个，与课程互补。

案例要回答“借鉴什么”：例如如何定义 AI 产品价值指标、如何验证需求、如何将试点推广至更多团队。产出可以是一页案例拆解或适用于本人项目的行动清单。

有实际案例摘要时提供「查看案例」，可在当前产物内展开或沿用既有详情容器；无案例材料时显示「待匹配案例」及筛选方向，不编造公司业绩或成功数据。

#### C. 应用实践与阶段成果

保留实践，将所学课程和案例用于实际工作。每项包含：关联发展重点、关联课程/案例、实践任务、时间范围、交付成果、验收方式、依赖条件。

默认时间安排可为第 1–30 天建立方法、第 31–60 天应用验证、第 61–90 天复盘沉淀。对已有经验员工不统一使用“认识岗位、跟岗观察、独立小任务”的新人模板。

课程、案例、实践通过同一发展重点关联，阶段概览仅引用内容名称和成果，不重复整段资源说明。建议学习顺序一目了然，但不要求完成前项才能阅读后项。

#### 时间预算

- “每周学习投入”计入课程、案例研读和学习整理；所有学习项合计校验，不分别声称每项都不超预算。
- 实践默认结合正常工作，额外投入单独说明；辅导用时独立展示。
- 默认安排可以留出复习与调整余量，不必填满预算。
- 页面展示的学习、实践和辅导时间均须落在当前计划周期内；收到周期调整后的计划版本时，展示对应安排，不保留过期日期。

### 3.6 辅导带教安排

回答「谁来支持、围绕什么辅导、什么时候开展、如何检验效果」。本节独立展示，并与发展重点、学习产出和实践成果关联。

| 内容 | 展示规则 |
| --- | --- |
| 建议导师 | 姓名/角色、专长与匹配理由；有已分配导师则引用，无则显示“导师待确认”及建议寻找的专长，不随机指定人员 |
| 带教目标 | 需要导师帮助解决的具体问题，对应发展重点 |
| 辅导方式 | 方案讨论、案例共研、实践点评、阶段复盘等，与目标匹配 |
| 时间安排 | 建议时间窗口、频次和单次时长；默认每两周一次，可按周期调整 |
| 本次议题 | 具体到需讨论或评审的内容，避免每次均写“成长沟通” |
| 员工准备 | 提前准备的方案、案例拆解、数据或问题清单 |
| 预期输出 | 明确反馈、改进建议、下一步行动与复盘结论 |
| 安排状态 | 显示“建议安排／待确认”；不显示已预约、已通知或已接受 |

默认 90 天示例可安排 6 次辅导，围绕目标对齐、案例讨论、验证方案点评、实践中期反馈、推广方案评审和最终复盘；周期不足时减少次数，不机械保留 6 次。导师角色与上级角色分别处理，不因导师未知就默认指定直属上级。

### 3.7 待确认事项

页面末尾集中列出真正影响使用的信息，并在相关条目就地标记，如目标岗位标准、课程材料、案例来源、导师和实践项目。缺失内容不阻止查看其他章节；不把整个“优劣势分析”藏进待确认折叠区。

## 4. 内容关联样例

以下是方案内容示例，不是新的员工事实或已匹配资源。实际课程和案例未提供时按“待匹配”处理。

| 分析依据 | 发展重点 | 课程学习 | 标杆案例 | 应用成果 | 带教支持 |
| --- | --- | --- | --- | --- | --- |
| 主管建议加强数据验证 | 建立产品验证闭环 | 待匹配：产品指标与实验验证，建议 2 小时 | 待匹配：AI 产品试点效果评估，建议研读 1 小时 | 当前项目的一份验证方案 | 导师点评指标是否支持关键决策 |
| 产品战略学习方向及目标岗位建议 | 提升规划与取舍能力 | 待匹配：产品战略与路线图，建议 3 小时 | 待匹配：从业务问题到产品路线图，建议研读 1 小时 | 一份路线图与优先级说明 | 讨论取舍依据及业务价值 |
| 主管建议加强规模化推广 | 沉淀推广方法 | 待匹配：产品推广与复盘，建议 2 小时 | 待匹配：从试点到多团队推广，建议研读 1 小时 | 一份推广方案或复盘清单 | 评审推广依赖和协作风险 |

学习资源初步合计 10 小时，分布于 90 天内，剩余学习预算用于整理、复习及调整；实践和辅导用时另列。每个发展重点至少关联一项学习/案例/实践及一种支持方式，避免只有评价、没有行动。

## 5. 页面内交互

### 5.1 阅读与定位

- 打开时展示计划概览和正文起始位置，沿用现有产物打开逻辑。
- 点击章节目录，滚动到对应章节；四个核心章节仍处于同一份连续文档中。
- 分析结论默认可见，较长依据可按需展开；展开不影响其他章节。
- 课程和案例有实际内容时可查看详情，无内容时展示待匹配说明，不提供无效入口。
- 关闭再打开仍为同一份计划；不新建产物或重置已保存的修改。

### 5.2 局部编辑

课程、案例、实践和辅导条目在所属区域提供编辑入口；复用现有编辑弹窗和默认 shadcn 控件，不引导用户回到前置澄清表单。

| 对象 | 可编辑内容 |
| --- | --- |
| 课程学习 | 学习主题/可用课程、计划时间、预计投入、学后产出 |
| 标杆案例 | 案例主题/可用案例、研读重点、时间、借鉴产出 |
| 应用实践 | 任务说明、时间范围、交付成果、验收方式 |
| 辅导带教 | 建议支持人、议题、方式、时间、员工准备及预期输出 |

### 5.3 内容一致性

- 所有条目关联明确的发展重点，避免出现课程、案例和辅导与目标无关的情况。

- 编辑后若超出学习预算或计划周期，在当前编辑区域指出问题，修正后再保存。

- 既有流程更新计划时，页面整体展示同一修订版本，避免概览目标与正文内容不一致。

## 6. 页面状态与视觉要求

| 情况 | 页面表现 |
| --- | --- |
| 分析依据不足 | 保留章节，说明待补充的资料，不生成确定性负面评价或能力分数 |
| 课程或案例未匹配 | 显示建议主题、用途及“待匹配”，不伪造资源来源或详情链接 |

| 局部编辑取消 | 保留原内容，不改变修订号 |
| 更新未成功 | 保留上一版完整内容，不展示成功反馈 |

- 沿用现有产物面板、经典与 Glass 主题。页面铺满面板画布，取消整页纸张式外边框、外层圆角卡片和灰底衬纸；内部使用 shadcn Card、Badge、Button、Progress 及既有编辑控件组织内容。宽面板支持内容双列，窄面板自然转为单列。预算进度明确表示用时安排比例，不表示学习完成率。
- 以标题、正文、辅助说明和语义标签区分层级；四个核心章节具有清晰边界。
- 页面内基础控件使用 shadcn 默认样式；不套用额外玻璃控件效果。
- 窄面板以单列卡片或条目呈现，避免宽表格横向滚动；全屏保持适宜正文宽度。
- 页面只保留一个主内容滚动区域，不给每个章节增加独立滚动条。
- 键盘可定位章节、打开详情、编辑及关闭；图标按钮有可访问名称，选中与错误状态不只靠颜色表达。

## 区域交互补充（2026-11-09）

删除概览前的发展介绍段落。概览支持对话框手动编辑目标岗位、周期与每周学习投入，保存更新当前计划并支持撤销；正式版保持只读。概览、各章节及多岗历练区域支持引用当前内容快照到当前会话 Composer，引用不自动发送，同一区域重复引用更新快照。章节目录保持原始字号和间距，宽度不足时使用左右翻页按钮，边界按钮禁用。

### 操作栏与按钮层级（2026-11-09）

章节翻页整合到 Tabs 内部，在最左侧隐藏左按钮、最右侧隐藏右按钮，无溢出时都隐藏。页底为独立固定操作栏，保留撤销并增加 primary“提交”，点击仅将提交提示词带入当前会话 Composer，发送后沿用既有提交流程。各添加/新增按钮使用 primary；区域引用使用 secondary，鼠标悬停或键盘聚焦区域时显示，触屏可见，隐藏时保持占位。
