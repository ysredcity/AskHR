## 动手前先写场景说明

新增场景属于较大改动，先给用户一段说明，确认后再写代码。说明需要覆盖：

| 字段 | 说明 |
| --- | --- |
| 入口 | 首页发送、历史对话、页面 Copilot、服务大厅召唤、薪酬智参中的哪一个或几个 |
| 触发提示词 | 用户输入什么会进入这个场景（`trigger.patterns`） |
| 专家与上下文 | 指定哪个专家；带入哪些技能、来源、数据快照 |
| 各轮执行步骤 | 每轮的 L1 摘要与 L3 步骤；只有「先规划、再分头执行、最后汇总」的长链路才用 L2 |
| 答案 | 每轮回复正文要点 |
| 业务卡 | 是否有产品块（如请假卡 `hr-leave`、确认卡、推荐追问） |
| 产物 | 名称、类型、内容来源 |
| 是否自动打开 | 每个产物是否在生成后自动打开右侧面板 |
| 澄清字段 | 是否需要澄清；字段、步数、默认值、推荐项 |
| 用户下一步与结束条件 | 推荐追问、确认动作，以及到哪一步场景结束 |

## 场景放在哪里

| 类型 | 位置 |
| --- | --- |
| 普通对话场景 | `components/agent-layout/conversation-data.ts` 的 `conversationScenes` |
| 场景中引用的产物数据 | `components/agent-layout/panel-data.ts` |
| 页面快照触发的分析回复 | `features/hr/business-intent.ts` 的 `createPanoramaScene`（按快照生成，不需要逐个写场景） |
| 首页推荐、专家、服务目录 | `features/hr/data.ts` |
| 多阶段业务流程（薪酬诊断） | `features/compensation/` |

数据与呈现分离：示例数据只写在数据文件里，不内嵌在 JSX 中。

## 普通场景的写法

```ts
// conversation-data.ts
export const conversationScenes: Record<string, ConversationScene> = {
  myScene: {
    trigger: { type: "keyword", patterns: ["专属动词短语"] },
    ...makeScene(
      "用户的第一句话",
      "智能体的回复正文（Markdown）",
      someArtifactTarget,               // 可选：从 panel-data.ts 引入
      { id: "card", type: "hr-leave" }, // 可选：产品块
    ),
  },
};
```

- `makeScene` 生成单轮场景：两步执行过程（核对范围 + 读取结果）、回复正文、可选的附件和产品块。多轮或复杂执行过程直接写 `turns` 数组，字段类型见 `agent-ui/script-engine/types.ts`。
- `trigger` 是子串匹配、最长命中优先：
  - 用专属的动词短语，不用「出差」「费用」这类宽泛词。
  - 不同场景的触发词不能重复，也不能互为子串；`check:scripts` 会拦下。
- 时间戳用 `formatTimestamp()` 或固定的「刚刚」，与现有数据格式一致。
- 回复正文里，影响判断的边界要写清楚（如「额度以考勤记录为准」「当前仅完成分析，尚未执行任何业务操作」）。不得暗示未执行的操作已经完成。

## 产物类型

右侧面板的产物是 `PanelView`（`components/agent-layout/panel-types.ts`）：

| type | 用途 |
| --- | --- |
| `file-preview` | 文档预览；`fileType: "HTML"` 时按 HTML 渲染（薪酬报告），`"Markdown"` 时按 Markdown 渲染 |
| `browser` | 网页预览 |
| `search-results` | 检索结果列表，点结果在面板内导航到 `browser` |
| `image` | 不进右侧面板，用蒙层图片查看器打开 |

- 执行步骤中的「已生成 X」和回复末尾的附件指向**同一个**产物对象。
- 只有用户能实际查看的产物才可点击；内部调用、脚本、接口步骤只做说明，不伪造入口。

## 复杂流程：以薪酬诊断为例

薪酬诊断是多阶段、有表单、有多个产物的流程，作为写法参考：

- 状态与阶段：`features/compensation/competitiveness.ts`（`Diagnosis` 类型、各阶段步骤名、产物名、`diagnosisScene()`）。
- 流程组件：`features/compensation/diagnosis-flow.tsx`（两步澄清表单、提交后分页回看）。
- 项目与触发：`features/compensation/data.ts`；主应用与子应用两个入口通过项目 `source` 区分导航显示，共用同一流程。
- 阶段：初步执行 → 初步结论 + 自动打开战略解码产物 + 两步澄清 → 诊断结果 + 自动打开竞争力分布产物 → 用户确认生成报告 → 两份最终报告（不自动打开）。

新的复杂流程优先复用这套组织方式和现有渲染器，不新建平行的对话组件。具体报告的版式属于业务场景，按对应设计稿实现，本 skill 不做规定。

## 自查清单

- [ ] 场景说明已经用户确认。
- [ ] 数据写在数据文件，JSX 中没有示例数据。
- [ ] 触发词专属、不与其他场景重复或互为子串。
- [ ] 执行过程层级反映真实复杂度，没有硬造 L2。
- [ ] 澄清字段 ≤ 10、按钮 ≤ 3、主按钮 ≤ 1；提交后转只读。
- [ ] 推荐追问 2–4 个，位于回复操作栏下方。
- [ ] 产物是否自动打开与场景说明一致。
- [ ] 写操作有确认；高风险确认卡字段齐全并设置 `awaitingApproval`（写在场景末轮）。
- [ ] `npm run gate` 通过（其中 `check:scripts` 校验场景数据）。
- [ ] 实际走一遍：从说明里的每个入口进入，确认能走到结束条件。

## 新员工成长计划

需求规格见 `docs/plans/2026-11-05-new-employee-growth-interaction.md`（仓库根目录）。

- 流程为发起需求 → 必要时补充信息 → 查看完整计划 → 按需调整。首次最多补充三个关键问题，已有信息不重复询问，可采用明确标注的建议值。
- AI 一次完成分析与编排，不将成长重点、学习实践和辅导安排设为逐步确认关卡；按阶段目标整合行动、资源、成果和支持人。
- 仅维护一份计划产物，首次生成自动打开，后续修订复用同一产物和 Tab；不额外提供暂存或保留按钮，不新增持久化。
- 局部可撤销修改直接应用并支持撤销；改变成长方向或覆盖手工修改时确认影响范围。本规则仅适用于计划内容编辑，不替代外部提交或影响他人的操作确认。
- 业务默认值仍以需求文档的待确认项为准；场景已接入新员工专区和首页；数据与状态在 `src/features/growth/` 及 HR Provider 中，主对话与 Copilot 使用同一 GrowthFlow。

成长计划当前实现边界：周期为3–365个整数天，每周学习投入大于0且不超过40小时；按阶段自动分配时间。学习资源以预设学习主题及案例主题呈现，不伪造课程报名或详情链接。自然语言支持周期、投入、岗位、目标、增减学习实践和重新制定；未识别的请求明确提示未应用，保留原计划。局部编辑可调整目标、行动、学习主题、成果及辅导，自动修改保留手工内容。场景规划对象统一取自“我的成长”：person 提供姓名、组织、岗位、职级及入职日期；employeePerformance 提供绩效与主管评价，development 提供任职认证进度，不维护独立人物档案，不沿用参考图中的姓名、绩效或资格记录。

成长计划回复末尾使用模板的 follow-up-suggestions 产品块呈现2–4个推荐追问，点击后预填 Composer，用户发送后执行；不另设调整按钮栏。执行过程使用共用 ReasoningPanel 展示简短规划依据，以 L1 → L3 展示步骤及说明，完成后自动折叠，产物步骤与附件指向同一个计划。

成长计划首轮先运行个人资料梳理（任职绩效 → 经历技能 → 发展重点），运行中隐藏澄清表单并禁用发送；完成后显示个人综合信息、职业发展评价，再展示澄清条件。信息已充分时自动进入计划生成阶段，减弱动效时即时推进；主对话和 Copilot 共用相同阶段状态。

成长计划澄清以目标岗位替代「希望达成什么」，表单为目标岗位、周期、每周投入三部分。目标岗位显示默认推荐与理由，按需展开方向选择器（同二级序列/跨二级序列/管理发展），各方向提供推荐和其他可选岗位；不用卡内Tabs或内部滚动。当前岗位取自档案，目标岗位独立保存，用于计划能力重点；方向切换默认选中该方向推荐，避免残留其他方向目标。提交后规划条件只读可回看；推荐不构成资格或晋升结论。

目标岗位采用两层Radio：第一层为首要推荐、同二级序列、跨二级序列、管理发展通道；默认首要推荐，岗位列表仅展示并选中首要推荐岗位。切换方向仅切换岗位列表，不修改实际已选岗位；仅用户点击具体岗位才修改目标和所属方向，其他岗位使用同一组单选卡；仅已选岗位使用强调边框、底色与已选标识，推荐为中性标签。目标岗位label后始终展示当前已选岗位，目标岗位区域不显示当前岗位，不再提供方向或其他岗位下拉。

目标岗位第一层分类Radio采用基础组件默认样式，标签仅排列圆点与文字，不加卡片边框、选中底色或卡片内边距；第二层岗位选项保留单选卡片。

目标岗位分类改用现有Tabs/TabsList/TabsTrigger/TabsContent分段组件，首要推荐、同二级序列、跨二级序列、管理发展通道切换仅浏览对应岗位。此为用户明确指定的澄清卡内Tabs场景例外，不扩展为通用表单规则；岗位仍用Radio手动选择。“已选：岗位”在目标岗位label同一行右侧展示，不增加切换行为提示文案。

岗位单选卡使用紧凑内边距与说明行距，不在卡内重复显示“已选”文字；以Radio选中态和边框底色表达，标题行右侧保留当前已选岗位。

首要推荐为资深产品经理P7；其他分类排除首要推荐岗位，同二级序列推荐AI产品经理P7，其他选项含产品规划专家和产品运营专家。分类Tabs沿用shadcn默认紧凑尺寸（水平列表h-8，宽度随内容），不添加min-height、整行等宽grid或字号放大；显式水平状态挂钩让已有基础件的默认水平布局生效。

### 成长计划产物页面（2026-11-08，V1.1）

只调整最终成长计划页面，需求见 `docs/plans/2026-11-08-growth-plan-page-requirements.md`（V1.1）。前置对话、执行过程、澄清表单与生成流程不变。

- 章节：概览 → 吸顶章节目录（随滚动高亮）→ 01 优劣势分析 → 02 建议发展方向 → 03 学习计划（课程学习、标杆案例）→ 04 实践历练（挑战任务、多岗历练）→ 05 辅导带教 → 待确认事项。不使用折叠内容。
- 优劣势分析只有优势（`success`）和待提升项（`warning`）两组；每条含结论、对目标岗位的意义和依据。
- 学习计划：紧凑条目，课程带按主题生成的本地封面；课程和案例都可从带搜索的对话框添加（课程库、案例库在 `catalog.ts`）或移除；内容本身不可编辑，只能修改每项的起止时间；总用时对照每周投入 × 周期的预算展示。
- 视觉层次：页面底色 `muted` 浅灰，章节为白色卡片；页头叠加 `primary` / `info` 弥散渐变；吸顶目录通栏。
- 实践历练：挑战任务与多岗历练可新增、编辑、移除，起止时间可直接修改；默认内容按目标岗位发展重点与发展方向生成。
- 辅导带教：只设 1 位导师，默认按汇报关系带出直属上级（`person.supervisor`），导师、辅导方式、辅导频次、具体措施直接在页面上修改，不支持新增或删除。
- 已删除「应用实践与阶段成果」。
- 页面内容存于 `plan.page`（`GrowthPage`），时间以「第几天」存储、按计划开始日展示；`reconcilePage` 在周期变化时按比例重排，目标岗位变化时重新生成默认内容并保留手工添加项。每次修改修订号 +1，可撤销最近一次。
- 页面内对话框通过 `usePanelPortal()` 挂载在产物面板内，遮罩只覆盖面板。
- 章节按步骤编号命名，标题与吸顶目录共用 `catalog.ts` 的 `steps`：优劣势分析 / 确定发展方向 / 配置学习计划 / 配置实践计划 / 辅导带教安排。
- 页面不随主题变化：底色为 `index.css` 的 `--growth-canvas`，Glass 下在 `liquid-glass.css` 复原文字色，浮层带 `data-component-style="default"`。
- 提交：`isSubmitIntent` 识别正向回复，`flow.tsx` 分阶段执行 `submitSteps`，完成后把当前计划存为 `state.submitted` 快照；`growthFinalArtifact`（`.final.growth.html`）只读渲染正式版。预览版名为「成长计划_预览版.html」。

成长计划为 HTML 网页制品：文件目标使用 `.growth.html` 与 HTML 类型，通过 HRFileBody 路由到交互页面；制品卡片显示员工成长计划 `.html` 文件名与网页说明，不展示虚构文件大小。页面采用铺满面板的网页布局，无整页文档外框，以容器宽度控制单双列。Progress 仅表示学习预算安排比例。

成长计划区域引用（2026-11-09）：概览、五个章节及实践子区域提供引用入口，截取当前区域内容作为可预览文件上下文，按当前 growth session 写入 sessionContexts，重复引用更新同一区域快照；GrowthFlow Composer 复用上下文添加/移除机制，不自动发送。概览编辑使用 Dialog 与目标岗位字段，保存同步条件、reconcilePage、修订及撤销；正式版只读。章节导航保持固定内容尺寸，横向溢出以左右翻页按钮浏览，不缩小字体或间距。

成长计划操作层级（2026-11-09）：目录翻页按钮整合在 Tabs 外观容器内部，左右滚动到边界时隐藏对应按钮；页面底部操作栏与内容滚动区分离，始终可见。预览版“提交”仅将“确认无误，提交成长计划”写入当前会话草稿，用户发送后执行；已提交且未修改时禁用。课程/案例添加与实践新增使用 primary；引用使用 secondary，在对应区域悬停、区域键盘聚焦时显示，触屏保持可见并保留占位。

成长计划细节修正（2026-11-09）：目录初始 analysis 步骤强制横向归零，后续仅计算并调整目录滚动容器的 scrollLeft，不使用 scrollIntoView 引发祖先滚动。底栏仅保留提交，不显示撤销按钮（对话撤销能力保留）。概览操作顺序为引用、编辑。

正式版成长计划（2026-11-09）：仅阅读提交快照，辅导导师、方式、频次与措施使用 dl 文本展示，不渲染只读/禁用输入框或 Select；通过 GrowthReadOnlyContext 统一阻止所有区域引用按钮。正式版无 footer，也不能打开概览编辑对话框；修改由用户在对话中发起，预览版保持现有编辑与提交入口。

预览版实践引用仅保留挑战任务与多岗历练两个子区域，“配置实践计划”章节不再提供整体引用入口，避免重复。

正式版步骤 Tabs 文案依次为：优劣势分析、发展方向、学习计划、实践计划、辅导带教安排。只调整正式版 Tabs 名称，预览版保留操作式名称。

成长计划审批语义（2026-11-10）：最后一步是提交审批，按钮预填“确认定稿，提交成长计划审批”；用户发送后创建审批流，完成状态为待审批、尚未生效。只读快照为审批稿，替代此前提交即正式版的说法。审批通过后计划才生效，提醒与推送需在生效后安排；当前未实现审批处理，不自动标记审批通过，不扩展审批人配置。

成长计划澄清与数据授权（2026-11-10）：澄清提交后保存独立条件快照，在首轮保留原回复及“已提交”只读表单，不随后续生成重写或移到最新轮。下一轮为敏感信息授权说明和共享 ConfirmCard，同意授权或选择仅使用已有档案后再执行生成；不用 SSO、无跳转链接、不以口头“已授权”替代卡片选择。授权记录保留，真实敏感数据未接入。主对话和 Copilot 复用该状态。

成长计划授权前执行（2026-11-10）：澄清提交进入独立 authorization 阶段，以 L1→L3 和简短规划依据展示核对条件、判断补充依据、整理用途三步，未许可前不读取敏感数据。运行中隐藏授权正文/卡片并禁用发送，完成后再请求授权；完成过程可回看，不覆盖前序只读表单。

IDP 历史回复保留：已完成回复的正文、执行记录、附件按轮固化在会话 replyHistory，后续消息不得因“非最后一轮”移除先前制品。推荐追问按最新轮动态呈现；同一产物仍沿用既有打开/修订路由，不因增加历史入口复制出新产物。
