# pangea-design-ai 基线

AskHR 最初用 pangea-design-ai 生成，`src/agent-ui/`、`src/components/agent-layout/`、`src/components/ui/`、`scripts/agent-ux/` 都是当时落地的代码。本文件摘录 AskHR **实际采纳**的 pangea 规则，以及 AskHR 的例外，让本 skill 在没有安装 pangea-design-ai 的工具里也能独立使用。

- 依据版本：pangea-design-ai v1.1.0（2026-11-02）的 `references/design.md`。AskHR 基于这一时期的模板生成，代码与之不一致时以代码为准。
- 装了 pangea-design-ai 且需要细节时，读它的 `references/design.md` 对应章节（下表给出章节号）；**不要**套用它的「新建产品」流程（两阶段需求闸门、脚手架初始化），AskHR 是增量迭代。
- pangea 升级不会自动影响 AskHR。需要跟进新规则时，先和用户确认，再改代码和本文件。

## 采纳的规则

### 技术栈与基础件（pangea SKILL.md）

- Vite + React 19 + TypeScript + Tailwind CSS v4 + shadcn v4；shadcn 底层是 **Base UI**（`@base-ui/react`），**不是 Radix**，两者 API 不兼容，参考外部 shadcn 示例前先确认。
- 基础件只用 `src/components/ui/` 中已有的，需要新的用 `npx shadcn add <component>`；不自建平行的按钮、输入框等基础控件。
- 图标只用 `lucide-react`；Toast 用 Sonner；Markdown 用 react-markdown + remark-gfm，正文排版统一交给排版层，不在业务组件里逐个元素设样式。
- 函数组件 + Hooks；状态只用 React 内置能力，放在应用壳层或最近的合适组件。
- 样式用 Tailwind utility + `cn()`，不用 CSS Module / styled-components。

### 信息分层（0.2）

任何新能力先归位到四层之一：委托（输入）/ 对话 / 过程 / 产物。

### 意图输入（3.1）

- 上下文按能否内联三分：文件库、最近对话、技能内联在消息中；本地上传文件是附件，显示在用户气泡上方。
- 同一个对象在侧栏、Composer、菜单、已选状态、消息流中使用同一个图标。

### 执行过程（3.2）

- 结论优先；已完成的执行过程默认收起，只有正在执行的过程默认展开。
- L1 是整轮任务状态；L2 只用于「先规划、再分头执行、最后汇总」的长链路；L3 是实际执行步骤。
- 简单任务用 L1 → L3，**不为层级完整硬造 L2**；有 L2 必须有可查看的 L3；L2 不嵌套 L2。
- 只有能让用户查看产物的动作才做成可点击 Badge；内部调用、脚本、接口只说明。
- 深度思考只用于复杂规划、协调执行或自纠错。

### 追问澄清（3.3）

- 待澄清事项 ≤ 2 用自然语言追问，> 2 或需要枚举用澄清表单卡片；选择优于输入；任何追问都可跳过。
- 表单卡片：字段 ≤ 10、优先单列；无 Tabs / 内部滚动；按钮 ≤ 3、主按钮 ≤ 1，放在底部；必填项未齐时禁用提交。
- 提交后字段转只读，标题栏显示「已提交」。日期等控件用项目基础件，不退回浏览器原生控件。

### 操作确认与风险（3.4、5.1）

- 只读直接执行；个人范围内、可撤销的写操作轻量确认；影响他人、资金、权限、正式数据或不可撤销的操作强确认。写操作不得静默执行。
- 高风险确认卡必须包含：对象、动作、影响范围、后果、操作人；不得用自然语言确认代替。
- 确认卡出现在「即将执行」的那一轮，不出现在只给建议的轮次。
- 待批准期间禁用整个输入区，并在会话列表标记「等待批准」；批准或拒绝后把结果回写对话流。

### 结果与产物（3.5）

- 以交付物为目标的任务，结论文字不算交付，必须给出可点击的产物附件；对话流内只展示摘要。
- 用户附件右对齐，智能体交付物左对齐，共用同一附件卡片与打开链路。
- 执行过程中的「已生成 X」与最终附件指向同一个产物。
- 与对话并排查看的产物用右侧面板 Tab；专注查看单个对象（图片）用蒙层查看器。
- 重复打开同一产物只切换 Tab；容器内跳转复用当前 Tab；面板顶部只保留全屏和关闭两个全局操作。
- 切换对话时立即清理上一对话的产物面板。

### 消息操作与后续引导（3.6、3.7）

- 悬停操作栏常驻占位，只切换透明度，不条件渲染。
- 复制后图标原地变对勾，不弹 Toast；点赞 / 点踩互斥，点踩打开反馈弹窗，提交后才置为已反馈态。
- 推荐追问 2–4 个，基于当前上下文。以下情况不出推荐：用户已结束对话、表达不满、任务失败且没有恢复路径、高风险操作刚完成。

### 一轮对话的结构（3.8）

- 消息块之间 20px；智能体身份到执行过程 8px；执行过程到正文 20px；用户消息内部 8px。
- 普通回复与表单提交后的续流程使用同一个回复块结构。
- 进入任意对话默认定位到最新一轮。

### 状态语言（4.1）

| 状态 | 表达 |
| --- | --- |
| 执行中 | Spinner + L1 标题扫光 |
| 等待用户回复 | 警示语义 +「需要你的回复」，只出现在最后一轮且用户尚未回复时 |
| 等待用户批准 | destructive 语义 +「需要你的批准」，会话列表标「等待批准」 |
| 完成未读 | 绿点，进入即消 |
| 已提交（表单） | 标题栏「已提交」+ 字段只读 |

五种状态不互相借用；状态不只靠颜色表达。

### 模拟执行与动效（4.2、4.3）

- 模拟执行分阶段推进，复用真实的运行中状态；减弱动效时压缩为立即推进。
- 动效只解释空间与状态变化；收起态不可交互、不可聚焦（`aria-hidden` + `inert`）；拖拽中不加过渡；同一种效果只有一个实现。

### 异常（5.2）

说清发生了什么、影响了什么、下一步怎么做；保留用户输入和已生成内容；不得在未完成时暗示已成功。

### 无障碍（5.3）

WCAG AA（亮暗两套都要满足）；纯图标按钮有 `aria-label` 与 Tooltip；键盘可完成核心操作、焦点可见；流式输出用 `role="log" aria-live="polite"`；图表提供文字替代。

### 视觉基础（6.1–6.3）

- 只用语义 Token；一组操作只有一个 `primary`；危险操作 `destructive` 且不设为默认；暗色由 Token 层覆盖。
- 字号：对话正文 15px / 1.6；辅助信息与过程文本 14px / 20px；极次要标注 12px。
- 已成契约的尺寸：动作 Badge 高 32px、最大宽 300px、全圆角；卡片类（澄清表单等）最大宽 600px、圆角 12px；桌面侧栏 240px、移动抽屉 320px；同一步骤的多个 Badge 纵向排列。

## AskHR 的例外与差异

| 方面 | pangea 规则 | AskHR 做法 |
| --- | --- | --- |
| 工作流程 | 新建产品先出需求文档、确认后再生成 | 增量迭代：微调直接改；新增页面 / Tab / 场景先给简短结构说明，确认后再写 |
| 产品模式 | 单一工作区或组合式工作台 | 组合式：主应用 Agent + 业务页面 Copilot + 薪酬智参子应用，共用对话组件与会话数据 |
| 响应式断点 | 沉浸式 980 / 740 / 659 | 无产物 660、有产物 980、产物强制全屏 740，另加 Copilot 专用 1280（见 interaction-rules.md） |
| 业务页 AI 按钮 | 主操作用 `primary` | 深灰 `bg-foreground` + Sparkles；`primary` 留给对话侧选中、进度与推荐标签 |
| 首屏引导 | 欢迎语 + 3–5 个推荐操作 | 欢迎语 + 专家选择 + 分类推荐指令 + 人资窗口期轮播 + 待办摘要 |
| 主题 | 只有 Token 主题 | 额外的 Liquid Glass 可选主题（见 glass-theme.md） |
| 导出 | 产物应可交付 | 最终报告的导出菜单只做展示，不执行真实导出 |
| 未接通入口 | — | 可以保持无跳转，不补假流程 |
| 检查脚本 | `check-tokens`、`check-scripts` | 沿用，另加 `check:askhr`（Glass 选择器挂载、已撤回功能与禁用文案） |
